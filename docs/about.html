About

One more option, for people who would rather their tools were small.

Who

Ngintip was created and first built by Nikko Enggaliano Pratama, a penetration tester at Seclab Indonesia, who spent enough days inside other people's proxies to want a different one.

Why

Not because the tools that exist are bad. Because there were few of them, and the ones in common use had grown heavy: hundreds of megabytes to install, a wait before the window appears, a project format you cannot open with anything else, and a machine that notices when the capture gets large.

The idea was simple and stubborn: an intercepting proxy should be light enough to forget it is running, fast enough that the capture is never the slow part, and honest enough that what you see is what crossed the wire. Everything in this documentation follows from those three.

What that turned into

  • Under 50 MB installed, because the interface runs in the webview your system already ships rather than a second browser.
  • Rust on the wire, so the window is never between a request and its answer.
  • One SQLite file per engagement, compressed to about a quarter of its size, that you can open with any SQLite client.
  • Bytes kept as bytes: an escape, a duplicate key or an oversized integer leaves exactly as you wrote it.

The Performance page has the measurements from a real engagement, and the footprint section explains the three decisions behind the size.

Where it is going

Development is in the open on GitHub. Bug reports and feature requests go in the issues, and the releases page carries a signed, notarized build for every platform.

If it saves you an hour on an engagement, it has done its job. If it does not fit how you work, there are other proxies, and having the choice is the whole point.
