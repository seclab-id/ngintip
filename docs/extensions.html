Extensions

Python hooks, with a clear line between changing traffic and merely reading it. This page is long on purpose: most extension bugs are a hook chosen in the wrong column.

The three kinds of hook

HookRunsUse it to
process_request
process_response		 Once per flow, on the wire Change live traffic: add a header, flip a parameter. What History shows is what crossed the wire.
decode_request
decode_response		 On demand, when a message is displayed or read Make an encrypted or packed body readable. Display only: the wire is never changed.
encode_request
encode_response		 On send, for an edited message Turn the readable form back into the wire form when you send from Repeater or forward an intercept.

A hook you do not define is skipped entirely, so an extension pays nothing for the stages it leaves out. For an encrypted API the pattern is decode_* to read and encode_* to send, with no process_* at all: the ciphertext on the wire stays exactly what the target sent and what you send back.

When each one fires. process_* runs as the message passes through the proxy, once. decode_* runs when something asks for the readable form, which means opening the flow in History, an agent reading it over MCP, or a message being held in Intercept, and it runs again each time. encode_* runs only on a send. If your log line is not appearing, that is almost always the reason.

The message object

MemberWhat it is
req.method, req.path, req.versionRequest line, readable and writable.
res.status, res.reason, res.versionStatus line, readable and writable.
m.hostShortcut for the Host header.
m.header(name, default)One header, case-insensitive.
m.headersget, set, add, remove, get_all, items(), dict(). Order is preserved.
m.body / m.textBytes, or the same thing decoded as text. Both assignable.
m.json() / m.set_json(obj)Parse or replace a JSON body; setting it fixes the Content-Type.
m.form() / m.set_form(dict)The same for application/x-www-form-urlencoded.
m.query() / m.set_query(dict)The query string of the request path, as a dict.
m.rawThe whole message as bytes, assignable if you would rather rebuild it yourself.

Mutate in place and return nothing, which is the recommended shape, or return a new message, bytes or a string. Content-Length is recomputed when the message is serialized, so you never count bytes by hand.

A hook that only looks at a message costs it nothing. If it returns nothing and changed nothing, the original bytes are passed through untouched, so a logging extension never makes History mark every flow as Modified, and a hook hunting for a Content-Length that disagrees with the body still sees the one that came off the wire.

The context

Every hook can take a second argument. It is optional: a one-argument hook still works.

FieldWhat it tells you
ctx.surfaceproxy, interceptor, repeater, intruder or test: where this message is being handled.
ctx.host, ctx.pathWhere it is going, without parsing the message yourself.
ctx.flow_idThe History row this belongs to: proxied traffic, a message held in the interceptor, a stored flow being decoded for display, and a repeater_send over MCP. None for a send from the Repeater tab or from Intruder, which keep their own history and are not rows in History at all.
ctx.editedTrue when a human actually changed the message before this send. Useful in encode_* to leave an untouched message alone.
ctx.stateA dict that survives between flows for as long as the worker lives. This is where a harvested key goes.
ctx.log(*args)Writes to the Debug console. print() goes there too; neither can corrupt the protocol.

Worked examples

1. Read an encrypted body, leave the wire alone

The common case: an API whose bodies are AES-encrypted, so History shows base64 and nothing else.

import base64, json
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad

KEY = bytes.fromhex("00112233445566778899aabbccddeeff")

def _dec(blob):
    raw = base64.b64decode(blob)
    iv, body = raw[:16], raw[16:]
    return unpad(AES.new(KEY, AES.MODE_CBC, iv).decrypt(body), 16)

def decode_response(res, ctx=None):
    if res.header("Content-Type", "").startswith("application/json"):
        return                      # already readable
    res.body = _dec(res.text)       # display only; the wire keeps its ciphertext
    res.set_header("Content-Type", "application/json")

def decode_request(req, ctx=None):
    if req.body:
        req.body = _dec(req.text)

History now shows a Wire and an Extension version side by side. Search, passive rules and the MCP server all see the readable one, which is the point: a finding you cannot grep for is a finding you will miss.

2. Send an edited body back encrypted

The other half. Without it, editing a decrypted body in Repeater would send plaintext to a target expecting AES.

import os
def _enc(data):
    iv = os.urandom(16)
    ct = AES.new(KEY, AES.MODE_CBC, iv).encrypt(pad(data, 16))
    return base64.b64encode(iv + ct)

def encode_request(req, ctx=None):
    if not req.body:
        return
    req.body = _enc(req.body)
    req.set_header("Content-Type", "text/plain")

Use ctx.edited if you want to re-encrypt only what a human actually touched, and let an untouched replay go out byte for byte as it arrived.

3. Harvest a session key at login and use it later

Many encrypted APIs hand you the key once, in the login response. ctx.state is a dict that outlives the flow, so the key you catch at 09:00 decrypts the traffic at 11:00. 

def decode_response(res, ctx=None):
    if ctx and ctx.path.endswith("/api/login"):
        ctx.state["key"] = bytes.fromhex(res.json()["sessionKey"])
        ctx.log("session key captured for", ctx.host)
        return
    key = ctx.state.get("key") if ctx else None
    if key and res.body:
        res.body = decrypt_with(key, res.body)

4. Add or rewrite a header on live traffic

def process_request(req, ctx=None):
    req.set_header("X-Forwarded-For", "127.0.0.1")
    req.headers.remove("If-None-Match")     # stop 304s hiding bodies

This one does change the wire, so History will show the message as it was actually sent. That is the trade.

5. Re-sign a request after you edit it

A body signed with an HMAC breaks the moment you touch it. Recompute the signature on the way out and the Repeater becomes usable against a signed API. 

import hashlib, hmac

SECRET = b"shared-secret"

def encode_request(req, ctx=None):
    mac = hmac.new(SECRET, req.body, hashlib.sha256).hexdigest()
    req.set_header("X-Signature", mac)

6. Unwrap a packed body for reading

Base64 inside JSON, gzip inside base64, a protobuf blob: anything you can undo in Python, you can read in the UI.

import gzip, base64

def decode_response(res, ctx=None):
    data = res.json()
    if "payload" in data:
        res.body = gzip.decompress(base64.b64decode(data["payload"]))

7. Do it only where it matters

ctx.surface keeps an experiment out of your capture: transform what you send by hand, and leave the browser's traffic exactly as it was. 

def process_request(req, ctx=None):
    if ctx and ctx.surface != "repeater":
        return
    req.set_header("X-Debug", "1")

8. Strip a header that is in your way

def process_response(res, ctx=None):
    for h in ("Content-Security-Policy", "X-Frame-Options", "Strict-Transport-Security"):
        res.headers.remove(h)

Useful while testing a UI, dishonest in a report: the target did send those headers. Turn the extension off before you capture evidence, or do it with a match and replace rule, which keeps the original beside the rewritten version.

Choosing where it runs

Each extension carries its own surface scope, which is how you keep an experiment out of your capture. The value is a list, and the names are the surfaces a message can arrive from:

ScopeThe extension runs on
allEverything. This is the default, and both or an empty value mean the same.
proxyTraffic flowing through the proxy from a browser or client.
interceptorMessages held in Intercept, before you forward them.
repeaterOnly what you send by hand. The browser's traffic is untouched.
intruderOnly the requests an attack generates.
repeater, intruderAny combination, separated by a comma, space, | or +.

So an extension that re-signs a body can be scoped to repeater alone: it fixes the requests you craft, and the recorded browser traffic stays exactly as the application sent it. The same value is readable at runtime as ctx.surface, so a single extension can also branch on it instead of being scoped.

The host scope applies first and independently. A host outside your target scope never reaches any extension, no matter what surface scope it has.

How it actually runs

Worth knowing, because it explains both the speed and the limits:

  • Each enabled extension is a long-lived Python process, started when you enable it. It is not restarted per request, which is why ctx.state can hold a key between flows and why an import cost is paid once.
  • The app talks to it over newline-delimited JSON on stdin and stdout, with the message passed as base64, so a body full of raw bytes survives the trip unchanged. Your print goes to stderr, which is why it can never corrupt that channel.
  • The app scans your file for the hooks it defines and only calls those. Define decode_response alone and nothing else costs you anything.
  • Calls are serialized per extension: one message in, one reply out. A hook that blocks for a second makes every message behind it wait a second, so do slow work once and cache it in ctx.state.
  • If the worker dies or an exception escapes your hook, the message passes through unchanged and the error is reported against that extension in the Debug console. Traffic is never dropped because a script broke.

Running and debugging

  • Debug console. print() and ctx.log() both land there. Nothing you print can corrupt the protocol between the app and your script.
  • Test tab. Dry-run one hook against a sample message and see the output and the log without touching a target.
  • Scope. Each extension has its own surface scope, and the host scope still applies: an out-of-scope host never reaches your code.
  • Virtualenv. Each extension gets its own, managed in the app, so pycryptodome for one target does not collide with another.
  • Failure. An exception is reported against that extension and the message passes through unchanged, rather than dropping traffic on the floor.
