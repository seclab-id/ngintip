MCP server

Let an agent read the capture, on a socket that never leaves your machine.

Ngintip can expose the capture over MCP. The server binds 127.0.0.1 only, and it is off until you start it.

What it exposes

GroupToolsFor
History history_list, history_get, history_search, ws_messages Page the capture, read one flow in halves or slices, search bodies, read what a socket carried.
Annotate history_set_note, history_set_color, history_get_color, findings_add Write back what the agent concluded, where you will see it: on the row, in your colours.
Scope scope_get, scope_set, scope_check Read the boundary, test a host against it, or set it.
Replay repeater_send, repeater_send_batch, repeater_groups, repeater_send_group, intruder_run Send a request again, a batch at once, a saved group, or run a payload set.
Passive passive_findings, passive_scan, passive_rules_get, passive_rules_set Read findings, rescan what is already captured, read or change the rules.
Organizer organizer_list, organizer_get, organizer_save, organizer_set Work the saved collections: list them, read one, add to them.
Vault vault_list, vault_get Fetch a credential the engagement needs without pasting it into a prompt.
Status proxy_status, extensions_status, extensions_enable, extension_toggle, extensions_logs Whether the proxy is capturing and why not, and what the extensions are doing.

The next release adds history_image, which renders a flow as the same evidence card the window produces, so an agent can hand you a picture instead of a wall of text.

The server documents itself too: with it running, open its /docs path for the tool list and argument reference of the build you actually have, rather than whichever one this page was written against.

Everything an agent can see is what you captured, which on an engagement is client data. Keep the server local, keep the client you point at it under your control, and treat an agent's access the way you treat the project file.
