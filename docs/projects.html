Projects and Footprint

One file per engagement, and not much else on your disk.

Projects

A project is a single SQLite .ngintip file: history, scope, match and replace rules, Repeater and Intruder tabs, Organizer collections, notes, colours, and each table's sort order. Open one, switch to another, and the app comes back the way you left it.

Switching is isolated by design. A swap cannot leave half of one engagement attached to another, and a result that arrives after the switch is dropped rather than filed under the wrong target.

Footprint

Three decisions account for the download size and for what runs on your machine:

No second browser
The interface runs in the webview the system already has: WebKit on macOS, WebView2 on Windows, WebKitGTK on Linux. The AppImage on the install page is what the same app costs when a package has to bring its own.
The GUI is not in the request path
tokio, hyper and rustls carry the traffic. HTTP/2 over ALPN and WebSocket are handled in Rust, bodies stream through, and the window hears about a flow after it has been forwarded.
No services
Nothing to install beside it, no account, no daemon left behind. The only sockets are the ones you open on localhost: the proxy, and the MCP server if you start it.
